# 非遗展品模块设计

## 目标

为非遗平台补齐成员 B 负责的非遗展品模块，支持匠人创建和编辑展品，所有访客浏览展品列表与详情，匠人在个人中心查看自己发布的展品。

## 范围

- 匠人新增展品：标题、封面、展品图片、作品介绍和技艺背景。
- 匠人编辑自己创建的展品。
- 展品列表和展品详情展示。
- 个人中心展示当前匠人自己的展品。
- 图片同时支持本地文件上传和图片 URL；本地上传优先。
- 展品详情保留到手作教程、用户作品模块的跳转入口。

不在本次范围内实现教程、用户作品、点赞、评论和管理员审核业务，但展品字段预留审核状态，并保持与已有数据库设计兼容。

## 技术方案

沿用项目当前的 Spring Boot 3、Spring Data JPA 和 Thymeleaf 单体架构。新增 `HeritageWork` 实体、仓储、服务和控制器。控制器负责登录和匠人角色校验，服务层负责展品归属校验以及图片保存。

图片上传使用 Spring 的 `MultipartFile`。文件保存到应用工作目录下的 `uploads/heritage`，对外通过 `/uploads/**` 静态资源映射访问；数据库只保存相对访问路径。若上传文件为空，则保存用户提供的 URL。文件名使用随机 UUID，避免重名和路径穿越。

## 数据模型

`heritage_work` 字段：

- `id`：主键。
- `craftsman_id`：发布匠人，关联 `user.id`。
- `title`：展品标题，必填。
- `cover_img`：封面图片地址，可空。
- `image_list`：展品图片地址，使用逗号分隔，可空。
- `description`：展品介绍，可空。
- `craft_background`：技艺背景，可空。
- `audit_status`：审核状态，默认 0 待审核。
- `audit_remark`：审核备注，可空。
- `create_time`：创建时间。

## 页面和路由

- `GET /work/list`：公开展品列表。
- `GET /work/{id}`：公开展品详情。
- `GET /work/create`：匠人新增页面。
- `POST /work/create`：保存新增展品。
- `GET /work/{id}/edit`：匠人编辑自己的展品。
- `POST /work/{id}/edit`：保存编辑结果。
- `GET /work/mine`：当前匠人的展品列表。

列表和详情不强制登录。新增、编辑和我的展品要求当前会话存在且角色为 `CRAFTSMAN`；编辑时还必须校验 `craftsman_id` 与当前用户一致。未登录或无权限请求返回首页并显示提示信息。

## 图片规则

封面和展品图分别支持文件上传与 URL 输入。对于每个字段，若存在非空上传文件则保存上传路径，否则保存 URL。展品图 URL 以逗号、换行或空格分隔，页面逐张展示。

## 验收标准

1. 匠人可以提交有效表单并在列表、详情和个人中心看到展品。
2. 匠人上传图片后，页面能通过生成的路径显示图片；未上传文件时 URL 能正常显示。
3. 匠人只能编辑自己的展品，普通用户和其他匠人不能编辑。
4. 访客可以浏览展品列表和详情，详情包含教程和用户作品跳转入口。
5. 表单对标题和文件类型进行基本校验，失败时返回表单并显示错误信息。
6. 项目原有测试和 Maven 构建不受影响。
