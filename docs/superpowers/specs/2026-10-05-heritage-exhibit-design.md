# 非遗展品详情与 3D 展示设计

## 目标

将当前已接入展品业务数据的详情页补全为可用的展品展示页面，并提供基于真实 GLB/GLTF 资源的交互式 3D 查看能力。保持已确认的米白背景、棕色主色、圆角卡片，以及左侧展示区、右侧展品信息、下方技艺背景的布局。

## 当前状态与范围

- 详情页已有封面图与多图合并、缩略图切换、图片放大弹窗、图片/3D 页签和技艺背景。
- 设计提出时 3D 区为二维透视演示；截至 2026-10-07，已替换为 Three.js / GLTFLoader，但真实非遗资源验收仍待完成。
- 本次范围包括真实 3D 模型加载、详情页交互与状态、模型地址数据字段、模型文件上传入口、数据库迁移说明和功能使用文档。
- 不在本次范围内制作或声称制作经过考证的非遗模型；有真实资源后通过上传或模型地址接入。

## 方案选择

1. **Three.js + GLB/GLTF（采用）**：通过 WebGL 渲染真实模型，提供旋转、缩放、复位、全屏及明确的加载状态；交互与视觉可按当前页面风格定制。
2. **`<model-viewer>`**：接入更简单，但查看器外观与状态交互的定制空间较少。
3. **CSS/Canvas 示意**：不需要模型资源，但不能满足真实 3D 展示要求，因此不作为最终实现。

## 页面与交互

- 保留“图片展廊 / 3D 展示”页签；键盘方向键、Home、End 可切换页签，切换后更新无障碍播报。
- 图片展廊展示封面图和 `imageList` 中去重后的图片；点击缩略图切换主图，点击主图打开可关闭的大图弹窗。图片为空或加载失败时显示可理解的空状态。
- 仅在用户打开 3D 页签后创建查看器；切回图片页签或文档隐藏时暂停动画，保留查看器以便恢复，离开页面且不进入往返缓存时释放渲染资源。
- 模型交互包括鼠标/触控拖动旋转、滚轮/触控缩放、复位视角和全屏。容器尺寸变化时更新渲染尺寸；离开页面时销毁渲染器和事件监听。
- 模型区域分别呈现等待加载、加载进度、加载成功、资源加载失败和浏览器不支持 WebGL 的状态。当前实现缺少模型时生成明确标注的“交互式 3D 演示”，不代表真实展品；真实模型配置后只加载该模型，失败时不以演示模型冒充成功。
- 3D 控件需有可见文字或无障碍名称、键盘焦点样式及状态播报；移动端控件适配窄屏。

## 数据与资源

- 在 `heritage_work` 增加可空的 `model_url` 字段，实体使用 `modelUrl` 属性；空值对既有展品保持兼容。
- 展品发布/编辑页提供模型 URL 和 GLB 文件上传。上传文件保存到 `/uploads/heritage/models/`，文件名使用随机 UUID；上传文件优先于 URL。
- 支持 GLB 单文件及 GLTF 主文件；若使用分离式 GLTF，引用的纹理/二进制资源必须能通过相同部署环境的静态 URL 正常访问。
- 数据库升级通过独立、可重复执行的迁移 SQL 添加字段；不要求重建已有数据库，也不覆盖展品数据。
- Three.js 运行时通过明确版本的 CDN 模块加载。若运行环境没有网络，页面仍可使用图片展廊，并显示 3D 资源不可用的明确状态。

## 验收标准

1. 已有图片展廊和详情信息保持可用，图片切换、大图弹窗和键盘页签操作可实际使用。
2. 配置有效 GLB/GLTF URL 或上传有效模型时，页面实际渲染模型；用户可旋转、缩放、复位和全屏查看。
3. 缺少 URL、模型 404/格式错误、WebGL 不可用时均显示明确状态，图片展廊仍可正常使用。
4. 数据库迁移不会删除现有记录，模型字段为空的历史记录仍可访问。
5. 发布/编辑表单能够保存模型 URL，上传 GLB 后详情页能够使用保存后的路径。
6. 项目文档说明功能边界、模型准备和存放方式、数据库迁移、操作方法、运行验证与常见故障。
7. 自动化测试通过，并用启动后的页面响应确认模型字段、3D 控件和状态文案已输出。

## 风险与后续

- 真实展品 3D 资源当前缺失，因此模型渲染框架可以先完成，但验收真实非遗模型的视觉正确性需要后续提供 `.glb`/`.gltf` 资源。
- CDN 受网络策略影响；无网络时不影响图片展廊，但真实模型无法下载，页面必须清晰告知用户。
- 大模型会影响加载时间和显存；文档建议压缩模型与纹理，并在失败时保留图片查看路径。
