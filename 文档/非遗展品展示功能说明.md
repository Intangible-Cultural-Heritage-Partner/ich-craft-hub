# 非遗展品展示功能说明

## 1. 功能概览

非遗展品详情页保留原有米白色视觉风格，并提供图片与 3D 预览两种展示方式。展品配置了 `.glb/.gltf` 时加载真实模型；尚未配置模型时，页面会生成一个明确标注为“交互式 3D 演示”的本地模型，保证演示环境可以直接体验旋转、缩放和全屏操作，同时不会把演示模型误认为真实非遗展品。

## 2. 图片展廊

- 展示封面图与展品图片列表，并自动去重。
- 点击缩略图切换主图，当前图片会有选中状态。
- 点击主图打开大图对话框，可使用 Esc 或关闭按钮返回。
- 没有图片时显示空状态，并提示发布者补充封面图或展品图片。
- 图片与 3D 通过顶部 Tab 切换，也支持键盘方向键、Home 和 End 操作。

## 3. 3D 查看器

打开“3D 预览”Tab 后，页面按需从 jsDelivr 加载固定版本的 Three.js 和 OrbitControls；只有配置真实模型 URL 时才额外加载 GLTFLoader。查看器支持：

- 鼠标或触摸拖动旋转模型；
- 鼠标滚轮或触摸手势缩放；
- “复位视角”恢复默认相机位置；
- “全屏查看”放大模型区域；
- 加载进度、加载失败、无模型和 WebGL 不支持提示；
- ResizeObserver 自适应容器大小；
- 离开页面时停止动画帧、断开观察器、释放控制器、几何体、材质、纹理和 WebGL 渲染器。

没有配置真实模型时，使用 Three.js 几何体生成演示器皿模型；该模型仅用于演示交互，不代表具体非遗展品。

配置真实模型后，演示模型不会加载，真实模型会自动计算包围盒并归一化尺寸，使不同尺寸的模型都能在同一查看区域内展示。

## 4. 模型上传与 URL

发布或编辑展品时可以选择以下方式之一：

1. 上传 `.glb` 或 `.gltf` 文件；
2. 填写可访问的模型 URL。

同时提供时，上传文件优先于 URL。服务层只接受 `.glb` 与 `.gltf` 扩展名，上传文件保存在 `uploads/heritage/models/`，数据库保存模型访问地址。推荐使用单文件 `.glb`；`.gltf` 通常还依赖同目录的 `.bin` 和纹理文件，必须保持相对路径并确保浏览器可以访问。

## 5. 数据库迁移

本功能新增 `heritage_work.model_url` 字段，对应实体属性 `HeritageWork.modelUrl`。首次部署需要执行：

```sql
SOURCE 开发/数据库/migration/20261005_add_heritage_work_model_url.sql;
```

如果数据库客户端不支持包含中文的路径，请进入迁移脚本所在目录后执行文件，或将路径替换为本机绝对路径。重复执行前请确认脚本中的字段存在性判断与当前 MySQL 版本兼容。

## 6. 运行要求

项目使用 Java 17。Windows PowerShell 中可以这样启动：

```powershell
$env:JAVA_HOME='D:\jdk17_hospot'
$env:Path=$env:JAVA_HOME\bin;$env:Path
.\mvnw.cmd spring-boot:run
```

若直接运行打包后的 JAR：

```powershell
& $env:JAVA_HOME\bin\java.exe `
  -Dfile.encoding=UTF-8 `
  -jar .\target\intangible_heritage-0.0.1-SNAPSHOT.jar `
  --spring.datasource.username=root `
  --spring.datasource.password=实际MySQL密码
```

页面、数据库连接和终端均应使用 UTF-8。详情页地址通常为 `http://localhost:8080/work/{id}`。

## 7. 网络与安全限制

- 查看器模块依赖 jsDelivr；离线或受限网络下，图片展廊仍可使用，但 3D 模块可能进入加载失败状态。
- HTTPS 页面不能加载 HTTP 模型 URL，否则浏览器可能拦截混合内容。
- `.gltf` 的外部 `.bin` 与纹理资源必须能通过 HTTP 访问，并正确配置 CORS。
- 只上传获得授权的模型，避免将个人信息或过大的文件放入公共目录。

## 8. 常见故障

| 现象 | 处理方式 |
| --- | --- |
| 显示交互式 3D 演示 | 当前展品尚未配置真实模型；在编辑展品页面上传 `.glb/.gltf` 或填写模型 URL 后，会优先加载真实模型。 |
| 显示“模型加载失败” | 检查 URL、文件扩展名、上传目录权限，以及 `.gltf` 的 `.bin` 和纹理依赖。 |
| 显示“浏览器不支持 WebGL” | 开启浏览器硬件加速，或更换现代浏览器。 |
| 一直加载或模块导入失败 | 检查浏览器网络、CDN 访问和控制台错误；先使用图片展廊。 |
| 中文出现乱码 | 确认文件保存为 UTF-8，并使用 Java 17 与 `-Dfile.encoding=UTF-8` 启动。 |

## 9. 当前验证边界

当前仓库已经实现真实 Three.js / GLTFLoader 接入、交互式演示模型和完整降级状态。仓库没有内置经过确认的真实非遗展品 `.glb/.gltf` 文件，因此演示模型只用于验证页面交互；真实非遗模型的视觉效果需要在获得合法模型资源后，通过编辑页上传或配置 URL 再进行验收。
